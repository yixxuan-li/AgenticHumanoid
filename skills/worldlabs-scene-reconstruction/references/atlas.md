# World Labs Atlas reconstruction

Use Atlas when requested or when generative completion of unseen surfaces is appropriate. Read the current [quickstart](https://docs.atlas.worldlabs.ai/quickstart.md), [video workflow](https://docs.atlas.worldlabs.ai/using-video-footage.md), and the installed official `atlas-splats` / `worldlabs-cli` skills. The official skills describe camera placement, visual review, and task execution. This reference adds simulator-integration requirements.

Install the official CLI and skills using their documented commands. Keep credentials in the CLI's private login or `WLT_API_KEY`; never put a key in a command, chat, source file, or committed request. A user-provided credential file may be read only as authorized; ignore it before staging repository changes. Operation results can contain temporary signed download URLs, so keep raw API responses private and untracked.

1. Select sharp, overlapping, time-ordered frames covering the entire recording. Start with 8–16 for a room. Submit real views together with `images2PosedRGBD`, choosing a supported output grid matching their aspect and enabling pose refinement when comparing views. Save the operation ID before polling.
2. Inspect the returned RGB, cameras, confidence, and depth as a unit. Find the floor and free camera space. Generate missing viewpoints in small rounds using `atlasGenerate` with depth returned. Inspect every generated view and preserve its provenance. Reject conflicting furniture or invented objects in observed space. Disclose completion of uncaptured areas.
3. Curate the input set before the long reconstruction. If a frame needs an exclusion mask, align it to that image/camera grid. The observed API contract requires `maskAsset` on every posed frame or none; use full-white keep masks for unaffected frames. Keep excluded RGB and corresponding depth out of the reconstruction through the mask.
4. Submit one refined `posedImages2Splats` task after review. Persist the request, idempotency key, operation ID, and status. Resume polling or downloading after interruption; do not start a duplicate reconstruction. Review the SPZ from source views and novel viewpoints using Spark or Blender.
5. Extract a textured mesh with `splats2Mesh`, optionally requesting upright collision boxes. Review this mesh separately from the splats: a good splat can produce opaque bridges, closed unsupported surfaces, or poor textures in the mesh. Stereo depth and density trimming are documented options for addressing specific observed extraction failures. Preserve earlier results and explain parameter changes.

Atlas cameras are camera-to-world, XYZW, normally RUB, in a Y-up frame. OpenCV reads the returned EXR rows top-down. Convert the world basis, camera rotations, geometry, and collision boxes together for a Z-up simulator. Estimate scale from an explicitly documented anchor; generated camera/depth units do not establish real metres. A conventional table height is still an assumption.

Use textured meshes or splats for appearance and separate solids for contact. Atlas meshes and fitted collision boxes are static; masses, friction, object ownership and articulated mechanisms are not recovered by that workflow. Do not count a static reconstructed chair as an interactive free body. Keep existing articulated assets separate unless registration and ownership have been validated.

Validate both native simulator exports. Check floor support, free-object drops, friction, penetrations, dependencies and scene placement. Reserve navigation routes before placing added benchmark props: a small floor object can close a conservative robot-clearance corridor. Bind reports to visual assets as well as XML, USD and manifests. Keep robot dimensions fixed during room calibration, and revalidate after rescaling.

For appearance review, use actual video frames excluded from reconstruction input and texture creation. Pose estimation using those frames is review-only; image agreement does not establish depth or metric accuracy. State separately what was tested in the splat renderer, mesh renderer, dynamics engine, and WBC.
